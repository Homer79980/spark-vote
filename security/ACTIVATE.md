# 上线管理员登录

此分支是待启用版本；填入真实项目配置、登记管理员并部署数据库规则之前，不要合并到正式页。GitHub 权限不能代替 Firebase 项目权限。

1. 项目所有者在本机终端运行 `npx firebase-tools login`，用管理 `playa-dc7ae` 的 Google 账号登录。不要在聊天或仓库提供密码、服务账号密钥或令牌。
2. 在该 Firebase 项目为 Web 应用取得公开配置，填写根目录的 `firebase-web-config.js`，包括 apiKey、projectId、appId、authDomain 及现用 databaseURL。为 Authentication 启用 Google 和 Anonymous，授权站点域名 homer79980.github.io。
3. 指定实际管理员。管理员在预发布页面用自己的 Google 账号登录一次，再由所有者从 Firebase Authentication 核对其 UID，在数据库管理端登记 `sparkVoteAdmins/<该 UID> = true`。首次登录未获准是预期现象。
4. **不要直接覆盖整库规则。** 先导出目前规则，检查根目录是否向下授予写权限；将本目录规则中的两条业务路径与原规则合并，确认其他应用保持原权限。若该实例仍依赖根目录的公共写权限，应先完成其他路径的权限拆分。只发布核对后的规则。
5. 与管理员商定换轮时间。在现有一轮投票进行中，不直接更换身份机制：旧匿名浏览器标识不等于新的 Firebase UID。若需保留同轮撤销和剩余名额，先设计并验证身份迁移。无需删除已有票数，不能为启用登录擅自开始新一轮。
6. 先在测试环境检查管理登录、匿名两种投票、官方模拟器权限用例；正式切换时协调数据库规则与 Pages 发布。普通投票者不填账号；管理员退出不会影响其投票身份。回退不能重新开放匿名管理写权限。

规则验证对象是管理员操作与选票所有权。500 个编号、分组限额和编号所属图片的完整业务校验目前仍在客户端；若用于需要防作弊的竞赛，应增加可信投票服务。
